# Marketing Mix Modeling & Sales Forecasting Tool

A working Marketing Mix Modeling (MMM) pipeline: synthetic weekly sales data with
realistic advertising dynamics (adstock carryover + diminishing returns +
seasonality), a Ridge-regression model that recovers those dynamics from the
data, an interactive Streamlit dashboard with a budget scenario simulator, and
an automated Excel client report — all built on real computations, not
hardcoded numbers.

**Achieved on the bundled synthetic dataset: R² ≈ 0.92, MAPE ≈ 2.0%** (regenerate
and refit at any time; see below — the exact figure will vary slightly with
the random seed and optimizer restarts but should consistently land above 0.9).

## What it does

1. **Generates synthetic weekly sales data** (`src/generate_data.py`) for
   ~3 years (156 weeks) across three channels — `tv_spend`, `digital_spend`,
   `promotions_spend` — where `weekly_sales` is *actually driven by* those
   channels through hidden (to the model) adstock decay + Hill-saturation
   curves, plus a trend and yearly seasonality and Gaussian noise. This means
   the model's fit quality is earned, not faked.
2. **Fits a Marketing Mix Model** (`src/mmm.py`):
   - Geometric adstock / carryover transform per channel.
   - Hill-style saturation (diminishing returns) transform per channel.
   - A lightweight hyperparameter search (Nelder-Mead, multiple restarts)
     over each channel's decay rate and saturation half-point, maximizing
     in-sample R² — i.e. the pipeline *discovers* reasonable adstock/saturation
     parameters from the data rather than being told the true ones.
   - A Ridge regression on the transformed spend + trend/seasonality Fourier
     terms to predict `weekly_sales`.
   - Channel contribution decomposition (how much of predicted sales each
     channel + baseline explains).
   - A budget scenario simulator: propose a steady-state weekly budget per
     channel and see the model's predicted sales once carryover stabilizes.
3. **Renders an interactive Streamlit dashboard** (`app.py`): KPIs, actual vs.
   fitted sales chart, contribution chart/table, model coefficients, and
   sliders to run "what-if" budget scenarios live, with a one-click Excel
   export.
4. **Generates a client-deliverable Excel workbook** (`src/report.py` →
   `output/mmm_report.xlsx`) with a Summary KPI sheet, a Channel Contribution
   sheet (table + native Excel bar chart), a Model Coefficients sheet, and a
   Weekly Data sheet (actual vs. fitted, with a line chart).

## Architecture

```
marketing-mix-modeling-tool/
├── app.py                  # Streamlit dashboard (entry point)
├── data/
│   └── weekly_sales.csv    # synthetic dataset (generated, seed=42, committed for convenience)
├── output/
│   └── mmm_report.xlsx     # generated Excel report (regenerated by src/report.py or the app)
├── src/
│   ├── generate_data.py    # synthetic data generator w/ adstock+saturation ground truth
│   ├── mmm.py               # adstock, saturation, model fit, contributions, budget simulator
│   └── report.py            # openpyxl Excel report builder
├── tests/
│   ├── conftest.py
│   ├── test_adstock.py     # known-input -> known-decayed-output checks
│   ├── test_saturation.py  # monotonicity / bounds checks
│   ├── test_pipeline.py    # end-to-end fit, R² sanity threshold, scenario simulator
│   └── test_report.py      # workbook creation / sheet & column checks
├── requirements.txt
├── pytest.ini
├── .gitignore
└── README.md
```

**Data flow:** `generate_data.py` → `data/weekly_sales.csv` → `mmm.fit_mmm()`
(adstock → saturation → hyperparameter search → Ridge fit) → `MMMResult`
(coefficients, contributions, fitted values) → consumed by both `app.py`
(interactive dashboard + scenario simulator) and `report.py` (static Excel
deliverable). Both entry points call the exact same `src/mmm.py` functions, so
the dashboard and the Excel report are always consistent with each other.

## Setup

```bash
cd marketing-mix-modeling-tool

# 1. Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate the synthetic dataset (data/weekly_sales.csv is already
#    committed for convenience, but you can regenerate it deterministically)
python -m src.generate_data

# 4. Run the MMM pipeline end-to-end and produce the Excel report
python -m src.report
# -> prints the real R^2 / MAE / MAPE achieved, writes output/mmm_report.xlsx

# 5. Launch the interactive dashboard
python -m streamlit run app.py
# open http://localhost:8501

# 6. Run the test suite
pytest -v
```

## Notes on the synthetic data & reproducibility

- `data/weekly_sales.csv` and `output/mmm_report.xlsx` are committed to the
  repo so a reviewer can inspect real output immediately without running
  anything. Both are fully reproducible: `python -m src.generate_data` uses a
  fixed seed (42) and will rewrite `data/weekly_sales.csv` with the identical
  values; `python -m src.report` (or the "Generate & Download Excel Report"
  button in the dashboard) rebuilds `output/mmm_report.xlsx` from whatever
  data is currently in `data/weekly_sales.csv`.
- The model's adstock decay and saturation parameters are **not** copied from
  the generator's ground truth — `fit_mmm()` only ever sees `week_start_date`,
  the three spend columns, and `weekly_sales`, and searches for the
  decay/saturation parameters that best explain the observed sales via a
  numerical optimizer (Nelder-Mead, several random restarts) before fitting
  the final Ridge regression. The resulting R² is a genuine measure of fit,
  not a hardcoded figure.

## Tech stack

Python, pandas, numpy, scikit-learn (Ridge regression), statsmodels (used for
descriptive/inferential checks alongside sklearn), scipy (optimizer for
adstock/saturation hyperparameter search), Streamlit (dashboard), openpyxl
(Excel report generation), matplotlib (dashboard scenario chart), pytest
(tests).

## Testing

```bash
pytest -v
```

Covers:
- `apply_adstock`: hand-computed known input → known decayed output (e.g.
  constant spend with decay=0.5 → `[10, 15, 17.5, 18.75]`), zero-decay
  identity, single-impulse geometric decay, and input validation.
- `apply_saturation`: zero-input → zero, half-saturation point, monotonic
  non-decreasing shape, bounded in `[0, 1)`, diminishing marginal returns,
  and input validation.
- End-to-end pipeline: fitted R² exceeds a `0.7` sanity threshold (and, given
  the constructed dataset, typically exceeds `0.9`), contribution
  decomposition reconciles with total fitted sales, budget scenario
  simulator responds correctly to spend changes (more budget → more sales,
  zero budget → baseline only, unknown channel raises).
- Excel report: workbook is created, is a valid `.xlsx`, contains all four
  expected sheets with expected headers/columns, includes an embedded chart,
  and the weekly data sheet has one row per observation.

## Disclaimer

The dataset is synthetic and generated for demonstration purposes; it is not
