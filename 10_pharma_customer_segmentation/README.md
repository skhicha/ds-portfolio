# Pharma Customer Segmentation & Targeting Analytics

A working physician-segmentation pipeline: synthetic prescriber data with
realistic, internally consistent behavioral structure, a PCA + K-Means
clustering model that rediscovers that structure from the data alone, a
decile-based targeting model that ranks and scores physicians for commercial
outreach, a polished interactive Streamlit dashboard, and an automated Excel
client report — all built on real computations, not hardcoded numbers.

**Achieved on the bundled synthetic dataset (500 physicians, seed=42):
k=4 segments, silhouette score ≈ 0.209, PCA explains ≈85.7% of variance in 7
components** (regenerate and re-cluster at any time; see below — exact
figures vary slightly with sample size and seed).

## What it does

1. **Generates synthetic physician/prescriber data** (`src/generate_data.py`)
   for 500 physicians across 5 specialties (Endocrinology, Primary Care,
   Internal Medicine, Cardiology, Nephrology), 6 regions, and 4 practice
   settings. Each physician is first assigned one of **5 hidden behavioral
   archetypes** (high-value loyalist, high-potential/low-share,
   digital-first emerging, low-priority/steady, declining/at-risk) that
   drives correlated, realistic values across patient panel demographics,
   total market prescription volume, the company product's volume/value/
   market share, and HCP engagement signals (digital engagement, rep visits,
   samples, peer/KOL influence). The archetype itself is never written to the
   output — the segmentation pipeline has to rediscover this structure from
   the observable columns alone, so the resulting silhouette score is
   genuinely earned.
2. **Runs PCA + K-Means segmentation** (`src/segment.py`):
   - Feature engineering (14 base features + 2 engineered ratios:
     new-to-total Rx ratio and whitespace volume) and standardization.
   - PCA dimensionality reduction (reduces to the smallest number of
     components reaching 85% cumulative explained variance; 7 of 16 features
     on the bundled data) with full explained-variance reporting.
   - A principled k selection: an elbow (inertia) + silhouette-score search
     across k=2-8. Silhouette alone maximizes at k=2 for almost any dataset
     with one well-separated supercluster (true here too), which is
     statistically correct but not actionable as a segmentation model, so the
     app/CLI recommend the silhouette-maximizing k within a configurable
     "business-actionable" floor (k ≥ 3 by default) instead of the
     unconstrained global optimum. Both the full search table and the
     unconstrained optimum are still shown, not hidden.
   - K-Means on the PCA-reduced space, plus per-segment profiling (size,
     mean feature values, a data-driven tier label ranked by mean Rx value).
3. **Builds a decile-based targeting model** (`src/targeting.py`): scores
   every physician on a composite 0-1 opportunity score (whitespace volume
   40%, current product value 25%, digital engagement 20%, peer influence
   15%, each min-max normalized), assigns deciles 1-10 (1 = top-priority 10%)
   using a tie-safe rank-based split, and produces a ranked target list. The
   model is validated two ways: the underlying segmentation's silhouette
   score, and a second silhouette score computed by treating the deciles
   themselves as cluster labels (this one lands near zero/slightly negative
   on the bundled data — an honest result, since a continuous ranking sliced
   into 10 equal bins isn't expected to form geometrically separated
   clusters the way the behavioral segments do).
4. **Renders a polished interactive Streamlit dashboard** (`app.py`): KPI
   row, a PCA scatter colored by segment, the elbow/silhouette search chart
   with the chosen k marked, a styled segment-profile table, a decile
   priority chart + filterable ranked target list, and a one-click Excel
   export — all generated from whatever data is currently loaded (bundled
   sample, a freshly generated sample at any size, or an uploaded CSV).
5. **Generates a client-deliverable Excel workbook** (`src/report.py` →
   `output/segmentation_report.xlsx`) with a Summary KPI sheet, a Cluster
   Profiles sheet (table + native Excel bar chart), a Targeting Deciles sheet
   (table + chart), and the full ranked Target List.

## Architecture

```
10_pharma_customer_segmentation/
├── app.py                          # Streamlit dashboard (entry point)
├── data/
│   └── physicians.csv              # synthetic dataset (generated, seed=42, committed for convenience)
├── output/
│   └── segmentation_report.xlsx    # generated Excel report (regenerated by src/report.py or the app)
├── src/
│   ├── generate_data.py            # synthetic data generator w/ hidden archetype ground truth
│   ├── segment.py                  # feature engineering, scaling, PCA, k selection, K-Means, profiling
│   ├── targeting.py                # opportunity scoring, decile assignment, decile validation
│   └── report.py                   # openpyxl Excel report builder
├── tests/
│   ├── conftest.py
│   ├── test_generate_data.py       # shape/ranges/reproducibility/domain checks
│   ├── test_segment.py             # PCA/K-Means correctness + edge cases
│   ├── test_targeting.py           # decile logic + edge cases
│   └── test_report.py              # workbook structure checks
├── requirements.txt
├── pytest.ini
├── .streamlit/config.toml
├── .gitignore
└── README.md
```

**Data flow:** `generate_data.py` → `data/physicians.csv` → `segment.segment()`
(feature engineering → scaling → PCA → k selection → K-Means → profiling) →
`SegmentationResult` → `targeting.build_target_list()` (opportunity score →
deciles → ranked list) → consumed by both `app.py` (interactive dashboard)
and `report.py` (static Excel deliverable). Both entry points call the exact
same `src/segment.py` and `src/targeting.py` functions, so the dashboard and
the Excel report are always consistent with each other.

## Setup

```bash
cd 10_pharma_customer_segmentation

# 1. Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate the synthetic dataset (data/physicians.csv is already
#    committed for convenience, but you can regenerate it deterministically)
python -m src.generate_data

# 4. Run the segmentation + targeting pipeline end-to-end and produce the
#    Excel report
python -m src.report
# -> prints the chosen k / silhouette score / decile silhouette score,
#    writes output/segmentation_report.xlsx

# 5. Launch the interactive dashboard
python -m streamlit run app.py
# open http://localhost:8501

# 6. Run the test suite
pytest -v
```

## Notes on the synthetic data & reproducibility

- `data/physicians.csv` and `output/segmentation_report.xlsx` are committed
  to the repo so a reviewer can inspect real output immediately without
  running anything. Both are fully reproducible: `python -m src.generate_data`
  uses a fixed seed (42) and will rewrite `data/physicians.csv` with the
  identical values; `python -m src.report` (or the "Generate & Download Excel
  Report" button in the dashboard) rebuilds `output/segmentation_report.xlsx`
  from whatever data is currently in `data/physicians.csv`.
- The 5 behavioral archetypes used to generate the data are **not** exposed
  to the segmentation pipeline — `segment()` only ever sees the observable
  physician-level columns and discovers cluster structure purely from PCA +
  K-Means on standardized features. The reported silhouette score is a
  genuine measure of cluster separation, not a hardcoded figure.

## Tech stack

Python, pandas, numpy, scikit-learn (StandardScaler, PCA, K-Means,

matplotlib (dashboard charts), pytest (tests).

## Testing

```bash
pytest -v
```

60 tests, all passing, covering:
- Data generation: output shape/columns, reproducibility for a given seed,
  categorical domains, numeric ranges, internal consistency (company Rx
  never exceeds total market Rx, tenure never exceeds years in practice),
  and `n=0`/`n=1` edge cases.
- PCA: output shape, non-increasing explained-variance ordering, cumulative
  variance sanity, explicit `n_components`, highly correlated/duplicated
  features, and empty input.
- K-Means / k selection: elbow + silhouette search table, the
  business-actionable k recommendation, expected cluster count, a silhouette
  floor on synthetic data (the 5 hidden archetypes mean a correctly specified
  k should recover genuine structure), and edge cases — single-cluster
  degenerate (all-identical) data, empty input, 1-2 row input, and a
  requested k larger than the number of distinct points (clipped, not
  crashed).
- Targeting: opportunity score bounds and divide-by-zero safety, decile
  assignment (always integers in 1-10, correct/even counts, decile 1 has the
  highest scores, tie-safe, bounded for small n), the decile-group silhouette
  validation metric, and the ranked target list / decile summary.
- Excel report: workbook is created, is a valid `.xlsx`, contains all four
  expected sheets with expected headers/columns, includes embedded charts,
  row counts match the input, and generation doesn't crash on a 5-row or
  0-row dataset.

The Streamlit app was additionally smoke-tested end-to-end in a real browser
(data generation, auto/manual k selection, PCA scatter, segment/decile
tables, and the Excel download) with zero console errors and zero server-side
exceptions across normal, small (n=5), and manually-chosen-k scenarios.
