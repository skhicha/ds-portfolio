# House Price Prediction

A working regression pipeline: EDA and feature engineering (log-transformed
target, missing-value treatment, IQR outlier clipping), four trained and
compared models (Linear Regression, Ridge, Random Forest, XGBoost), a
RandomizedSearchCV hyperparameter search on the strongest baseline, and a
polished interactive Streamlit app for live price prediction with feature
importances — all built on real, reproducible computations.

**Achieved on the bundled dataset (20,640 rows, 80/20 split, seed=42):
best baseline is XGBoost at RMSE ≈ $48,576 / R² ≈ 0.820; the tuned Random
Forest (RandomizedSearchCV, 20 iterations × 5-fold CV) reaches RMSE ≈ $50,610
/ R² ≈ 0.805** (see "Results" below for the full comparison table and exact
numbers from the committed run; re-running `python -m src.train` reproduces
these to the model's own internal randomness but with the same `random_state`
seeds).

## An honest note on the dataset

The original target for this project (and the resume line it's based on) was
the Ames Housing dataset. At execution time, the pipeline first tries to pull
a real Ames Housing CSV from a public GitHub mirror; when that's unavailable
(as it reliably is here — no guaranteed network access to arbitrary third
party mirrors), it falls back to `sklearn.datasets.fetch_california_housing`:
a free, bundled-with-scikit-learn dataset with the same regression shape
(continuous numeric features → a continuous home-value target). **This
project's committed, reproducible behavior trains and evaluates on California
Housing data, not real Ames Housing data.** The pipeline architecture,
feature engineering, model comparison, tuning, and Streamlit app are exactly
what they'd be for Ames — only the underlying rows differ.

## What it does

1. **Loads the dataset** (`src/data.py`): attempts the real Ames Housing CSV
   first, falls back to California Housing (8 numeric features: median
   income, house age, average rooms/bedrooms, population, average occupancy,
   latitude, longitude → target `MedHouseVal`, scaled to dollars).
2. **Engineers features** (`src/features.py`): median/mode imputation for any
   missing values (never touching the target column), IQR-based outlier
   clipping (winsorizing, not row-dropping, so alignment with the target is
   always preserved), and a log-transform of the target with its exact
   inverse for converting predictions back to dollars.
3. **Trains and compares four models** (`src/train.py`) on an 80/20,
   `random_state=42` split: Linear Regression, Ridge (alpha=1.0), Random
   Forest (100 trees), and XGBoost (100 trees, lr=0.1) — all trained on the
   log target, evaluated on RMSE/R²/MAE after converting predictions back to
   the original dollar scale.
4. **Tunes the Random Forest** with `RandomizedSearchCV` (20 parameter
   combinations × 5-fold CV, scored on negative RMSE) over
   n_estimators/max_depth/min_samples_split/min_samples_leaf/max_features,
   and persists the tuned model + feature names + full metrics to `models/`.
5. **Predicts interactively** (`src/predict.py` + `app.py`): given a
   (possibly partial) dict of feature values, fills in missing ones with
   sane defaults, predicts a price, and surfaces feature importances — all
   through a polished Streamlit dashboard with sliders scoped to realistic
   per-feature ranges (not the old flat script's blanket 0–10 sliders, which
   made no sense for features like latitude or population).

## Architecture

```
03_House_Price_Prediction/
├── app.py                   # Streamlit dashboard (entry point)
├── models/
│   ├── house_price_model.pkl   # tuned Random Forest (generated by src/train.py; gitignored - see note below)
│   ├── feature_names.pkl       # ordered feature name list
│   └── metrics.json            # full metrics from the last training run
├── src/
│   ├── data.py               # dataset loading (Ames URL -> California Housing fallback)
│   ├── features.py           # log-transform, missing values, IQR outlier clipping
│   ├── train.py               # model comparison, RandomizedSearchCV tuning, persistence
│   └── predict.py             # inference: input building, prediction, feature importances
├── tests/
│   ├── conftest.py
│   ├── test_data.py
│   ├── test_features.py
│   ├── test_train.py
│   └── test_predict.py
├── requirements.txt
├── pytest.ini
├── .streamlit/config.toml
├── .gitignore
└── README.md
```

**Data flow:** `data.load_dataset()` → `features.engineer_features()` →
`train.run_training()` (model comparison → RandomizedSearchCV tuning →
`models/house_price_model.pkl` + `metrics.json`) → consumed by both
`app.py` (interactive prediction) and `tests/` via `predict.predict_price()`.

**A note on `models/house_price_model.pkl`:** an unpruned (`max_depth=None`)
Random Forest with 300 trees on this dataset serializes to ~400MB+, well over
GitHub's 100MB file-size limit, so this one binary is gitignored rather than
committed (`feature_names.pkl` and `metrics.json` — which carry the numbers
quoted in this README — are tiny and are committed). Run `python -m src.train`
once after cloning to regenerate it locally before launching `app.py`.
The app and the CLI pipeline call the exact same `src/` functions.

## Setup

```bash
cd 03_House_Price_Prediction

# 1. Create and activate a virtual environment
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Run the full train/compare/tune pipeline
python -m src.train
# -> prints the 4-model comparison table, the RandomizedSearchCV best
#    params, and the tuned model's RMSE/R2/MAE; writes models/*.pkl + metrics.json

# 4. Launch the interactive dashboard
streamlit run app.py
# open http://localhost:8501

# 5. Run the test suite
pytest -v
```

## Results

Baseline comparison (80/20 split, `random_state=42`, metrics on the original
dollar scale after inverting the log-transformed predictions):

| Model             | RMSE      | R²     | MAE       |
|-------------------|-----------|--------|-----------|
| Linear Regression | $66,695   | 0.6605 | $45,746   |
| Ridge Regression  | $66,690   | 0.6606 | $45,745   |
| Random Forest     | $51,218   | 0.7998 | $32,087   |
| **XGBoost**       | **$48,576** | **0.8199** | **$31,414** |

**Best baseline: XGBoost.**

RandomizedSearchCV tuning (Random Forest, 20 iterations × 5-fold CV):

- Best params: `n_estimators=300, max_depth=None, min_samples_split=2, min_samples_leaf=1, max_features=0.5`
- Tuned Random Forest: RMSE $50,610 · R² 0.8045 · MAE $31,698

The tuned Random Forest improves meaningfully over the untuned Random Forest
baseline but doesn't quite catch the untuned XGBoost on this dataset — an
honest result from an actual run, not a cherry-picked one. (The pipeline
tunes Random Forest specifically because that was the model the original
notebook picked as its "best baseline" to tune; XGBoost is reported
transparently as the stronger model here.)

## Testing

```bash
pytest -v
```

35 tests, all passing, covering:
- Data loading: shape/columns, target strictly positive and dollar-scaled,
  no missing values, and the Ames-URL-failure fallback path.
- Feature engineering: log-transform round-trip correctness and rejection of
  non-positive targets, missing-value imputation (numeric median,
  categorical mode, target column never imputed), IQR outlier clipping
  (extreme outliers clipped, row count/alignment preserved, constant columns
  untouched), and the full `engineer_features` pipeline on synthetic data
  with planted missing values and an outlier.
- Training: data preparation produces a correctly log-transformed target
  aligned with its features, all four baseline models fit and evaluate
  without error, and the full `run_training` pipeline (comparison + tuning)
  produces sane, better-than-naive RMSE on a synthetic held-out split.
- Prediction: input-frame building handles complete/partial/empty/garbage/
  out-of-range feature dicts without crashing, `predict_price` returns a
  sane shape with a positive price and aligned feature importances (or
  `None` for models without `feature_importances_`), and `load_model` raises
  a clear error when artifacts are missing.

The Streamlit app was additionally run live in headless mode
(`streamlit run app.py --server.headless true`) and confirmed to serve
HTTP 200 with no server-side exceptions.
